# 项目启动与交接规范（AGENTS 附件）

> 本文件由 `AGENTS.md` 第①条与第⑦条引用，只在「新项目启动 / 写 HANDOFF / 交接」时加载；不随会话自动加载。
> 主文件：`AGENTS.md`（操作白皮书）。

## 一、新项目启动

1. **判定**：无现成 HANDOFF、任务与已有项目不重叠 → 按新项目处理。
2. **问答卡片**（`ask_user_question`）先拿两样：
   - **项目名**：正式名留档（HANDOFF 文件名 / 目录 / 交付物），简称日常交流用；
   - **项目方向**：一句话目标 + 不做什么。
   - 不拿信息不开工；不自拟名字。
3. **接入任务系统**：按白皮书第②条分化任务（父任务 = 阶段/大块交付，子任务 = 可独立验收的动作）。
4. **建骨架**：按 §二 建 HANDOFF 骨架（目标 / 文件地图 / 标准流程 / 踩坑索引 / 结论日志）。
5. **之后每轮**：动工 → 交付 → 回写 HANDOFF 结论日志。

## 二、HANDOFF 创作规则

### 2.1 文件与位置

- 一项目一 HANDOFF：`F:\DSH\projects\<项目名>\HANDOFF-*.md`；已有项目沿用原路径，不强制迁移。
- 命名：`HANDOFF-<项目简称>_<创建日期>.md`；同项目多个子文档可加 `-归档-<日期>` 后缀。
- 一个项目组 = 一组独立任务与交付物 = 一份 HANDOFF，互不共用。

### 2.2 骨架结构（动工前必建）

```markdown
# HANDOFF：<项目名>（简称：<简称>）

> 项目组：<一句话> | 创建：<日期>
> 交付物：<列表> | 目录：<路径>

## 1 目标
## 2 文件地图
## 3 标准流程
## 4 踩坑索引
## 5 结论日志（每轮追加）
```

- §1 目标：解决什么、不解决什么、验收标准。
- §2 文件地图：代码 / 脚本 / 文档路径一览，标注「改哪个、别动哪个」。
- §3 标准流程：从零到交付的步骤，含验证方式。
- §4 踩坑索引：已踩过的坑 + 正确做法，只增不删。
- §5 结论日志：每轮改动结束追加一条（日期 + 结论 + 证据路径），只追加不覆盖。

### 2.3 每轮更新

- 每轮改动结束追加一条结论；不重写历史条目。
- 结论写「做了什么 / 怎么验证 / 证据在哪」，不写过程流水账。
- 结论日志按日期排序，同一项目保持一致。

### 2.4 已验收内容归档（目录 + 超链接）

- 已验收、已成事实、不再影响后续决策的内容，从正文移入「归档」区块，正文只留链接。
- 归档区块用目录 + 锚点链接组织：

```markdown
## 归档（已验收，按需再读）

- [2026-10-30 视觉 Key 核对](#arch-20261030-vision)
- [2026-11-05 任务插件增量接口](#arch-20261105-task-edit)

<a id="arch-20261030-vision"></a>
### 2026-10-30 视觉 Key 核对
...
```

- 归档超过一屏时，拆到 `HANDOFF-<项目>-归档-<日期>.md`，HANDOFF 只留一行链接。
- 目的：新会话只加载「仍需要的部分」，不把旧内容全量读入上下文。

### 2.5 交接（新会话接入）

- 新会话先读 HANDOFF §1–§4（目标 / 文件地图 / 标准流程 / 踩坑索引），不读归档与 §5 历史全文。
- 需要历史或旧结论时，按 §2.4 目录跳转，只读被点名的锚点或指定归档文件。


### 2.6 压缩与删减（防止无限膨胀）

- **体积预算**：单个 HANDOFF 正文（§1–§5，不含归档）≤ 250 行或 12KB；超出时先归档再删，不靠砍正文硬塞。
- **结论日志滚动**：§5 只保留最近 10 条；更早的按「日期 + 一行摘要」移入 `HANDOFF-<项目>-归档-<日期>.md`，正文只留链接。
- **踩坑索引清理**：已解决、过时的坑移入归档；保留的条目只写「坑 → 正确做法」一句，不写过程。
- **文件地图与流程**：过期条目直接改或删，不留历史版本。
- **删减时机**：任务列表出现新完成任务时检查一次体积（与 offload 的 delivery 触发同源）；交接前必查；触发归档时同步执行。
- **单一事实来源**：同一事实只写一处（正文或某份附件），其余位置用链接，禁止两处各写一份。

### 2.7 按需读取细则

- **交接**：只读 §1–§4；§5 与归档默认不读。
- **查历史**：按 §2.4 目录跳转，只读点名的锚点；跨文件只读最新一份归档，旧归档默认不读。
- **查项目**：直接按目录 / 文件名进入，不依赖全局索引表。
- **单次读取**：以当前问题需要的节为限，不整份加载归档文件。

## 三、与白皮书的分工

- 白皮书：常驻规则（第〇–③ 条）与索引（第④–⑥、⑨条指向附件），每次会话自动加载。
- 本文件：项目启动 + HANDOFF 创作 + 交接，按需加载。
- 冲突时以白皮书「用户当轮指令 > 白皮书 > 项目 HANDOFF」的优先级为准。
